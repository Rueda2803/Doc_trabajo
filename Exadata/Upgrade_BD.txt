-------------------------------------------------------------------------------
   Upgrade de Cluster en un Exadata
-------------------------------------------------------------------------------
Referencia: https://docs.oracle.com/en/engineered-systems/exadata-database-machine/dbmin/upgrade-cluster.html

NOTA: Descargar la versión más reciente de OEDACLI para linux: https://www.oracle.com/database/technologies/oeda-downloads.html

Utilice este comando para actualizar un clúster de Oracle Grid Infrastructure, ya sea dentro de la misma versión principal o entre versiones principales distintas.

Syntax:
UPGRADE CLUSTER
   GIVERSION=Grid_relnum
   GIHOMELOC=Grid_home_dir
WHERE 
   { CLUSTERNAME=cluster_name [ STEPNAME=step_name ] | 
     CLUSTERNUMBER=cluster_number [ STEPNAME=step_name ] | 
     ID=cluster_id [ STEPNAME=step_name ] }

Argumentos

GIVERSION: La versión del software Oracle Grid Infrastructure a la que se está actualizando, incluida la actualización de lanzamiento (RU). Por ejemplo, 19.26.0.0.250121.

GIHOMELOC: La ubicación de destino del directorio raíz (home) de Oracle Grid Infrastructure.

Los siguientes argumentos están disponibles en la cláusula WHERE:

CLUSTERNUMBER: Especifica el número del clúster en el archivo es.xml, comenzando por 1.

CLUSTERNAME: Especifica el nombre del clúster.

ID: Especifica el ID del clúster en el archivo es.xml.

STEPNAME: Especifica, opcionalmente, el paso individual de la actualización:

1. ADD_HOME
2. CONFIG_HOME
3. RUN_ROOTSCRIPT
4. DELETE_OLDHOME

Usage Notes:

>El comando permite actualizar un clúster a una versión posterior dentro de la misma versión principal o a una versión principal más reciente; por ejemplo, actualizar de Oracle Grid Infrastructure versión 19c a la versión 26ai.

>Este comando solo permite actualizar un clúster en una implementación de máquina virtual (VM); no se puede utilizar para actualizar un clúster en una implementación física (*bare-metal*).

>Si no se especifica el parámetro STEPNAME, se ejecutan los pasos ADD_HOME y CONFIG_HOME.

>El paso RUN_ROOTSCRIPT ejecuta el script rootupgrade.sh de forma secuencial y escalonada (*rolling mode*) en todos los nodos. Este paso también reinicia las instancias de base de datos en cada uno de los nodos.

>Una vez ejecutado el paso DELETE_OLDHOME junto con el comando UPGRADE CLUSTER, no es posible utilizar posteriormente el comando DOWNGRADE CLUSTER para revertir la actualización.

Ejemplo: 

Este ejemplo muestra los tres primeros pasos (ADD_HOME, CONFIG_HOME y RUN_ROOTSCRIPT) de una actualización del clúster paso a paso. Al finalizar este ejemplo, el clúster está actualizado, pero todavía es posible revertir la actualización (realizar un *downgrade*) porque no se ha ejecutado el paso DELETE_OLDHOME.
